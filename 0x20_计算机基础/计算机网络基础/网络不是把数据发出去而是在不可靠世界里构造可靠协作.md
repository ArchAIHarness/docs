# 网络不是把数据发出去，而是在不可靠世界里构造可靠协作

很多人学习计算机网络时，会从 OSI 七层模型开始背。分层模型重要，但如果只背层次，很容易忽略网络的核心问题：网络面对的是一个天然不可靠的世界。

消息可能丢，包可能乱序，链路可能拥塞，节点可能宕机，DNS 可能解析失败，证书可能过期，服务可能超时。

所以，网络的本质不是“把数据发出去”，而是在不可靠环境中构造尽可能可靠、可理解、可恢复的协作机制。

## 一、IP：尽力而为，不保证可靠

IP 协议负责把数据包从一个主机送往另一个主机。它提供寻址和路由能力，但不承诺数据一定到达，也不保证顺序。

IP 的设计哲学是“尽力而为”：网络层尽量转发，失败时不承担端到端可靠性责任。

这让网络核心保持简单，把复杂的可靠性问题交给端系统处理。

## 二、TCP：在不可靠 IP 之上构造可靠字节流

TCP 的价值在于，它在不可靠的 IP 网络之上，为应用提供可靠、有序、面向连接的字节流。

为了做到这一点，TCP 引入了：

1. 序列号：识别数据顺序。
2. 确认应答：确认哪些数据已经收到。
3. 重传机制：丢包后重新发送。
4. 流量控制：避免接收方被压垮。
5. 拥塞控制：避免网络整体崩溃。

应用看到的是稳定连接，底层做的是纠错、排序、重试和调节。

## 三、HTTP：把字节流变成应用语义

TCP 只负责可靠传输，并不理解业务语义。HTTP 定义了请求、响应、方法、状态码、Header 和 Body。

```text
GET /users/1
POST /orders
404 Not Found
500 Internal Server Error
```

HTTP 的价值是让服务之间能够用统一格式表达意图和结果。网络工程不是只有连通性，还包括语义清晰性。

## 四、DNS 和 TLS：名字与信任

DNS 解决“名字到地址”的问题。用户访问的是域名，机器连接的是 IP 地址。

TLS 解决“信任和加密”的问题。它保证通信内容不被轻易窃听和篡改，并通过证书链确认对方身份。

一次 HTTPS 请求，背后通常包含：DNS 解析、TCP 握手、TLS 握手、HTTP 请求响应。任何一个环节出问题，请求都可能失败。

## 五、工程视角

真实系统中，请求失败很少只有一个原因。常见问题包括：

- DNS 解析慢或失败。
- TCP 建连超时。
- TLS 证书过期或握手失败。
- 服务端线程池耗尽。
- 网关限流。
- 负载均衡摘除不及时。
- 客户端没有设置超时。
- 重试策略放大故障。

因此，网络问题不能只看“通不通”，还要看解析、建连、加密、传输、应用处理和错误恢复。

## 六、常见误区

### 误区一：网络分层只是考试知识

分层的意义是分离职责。每一层解决一类问题，也引入一类边界。

### 误区二：TCP 可靠，所以应用不用处理失败

TCP 只能保证连接内字节流的可靠性，不能保证服务端一定成功处理业务。

### 误区三：重试总能提高成功率

没有退避、幂等和限流的重试，会把局部故障放大成系统故障。

## 七、实践建议

1. 给所有网络调用设置超时。
2. 对可重试操作设计幂等键。
3. 区分连接失败、读取超时、业务失败和限流失败。
4. 对关键链路记录 DNS、建连、TLS、首包和总耗时。
5. 不要把网络当成本地函数调用。

## 结语

网络工程的难点不在“发送数据”，而在不可靠世界里构造可靠协作。理解这一点，才能真正理解协议、网关、重试、限流和可观测性。
