# 本地大模型运行实践指南

> **阅读对象**:AI 应用开发者、平台工程师、技术负责人
> **适用场景**:本地运行 LLM、验证模型 API、对比 LM Studio 与 Ollama
> **关联阅读**:[OpenCode 全体系深度解析](./OpenCode全体系深度解析.md)、[Agent Skills 实践指南](./AgentSkills实践指南.md)

本文整理本地运行大模型的技术选型、LM Studio 与 Ollama 的搭建流程、OpenAI 兼容 API 调用方式、嵌入模型调用方式,以及常见并发问题的处理方案。

## 1. 需求分析

本地化运行 LLM 前需要确认两件事:

1. 当前硬件配置是否能支撑目标模型。
2. 使用哪种运行平台加载、管理和调用模型。

常见模型来源包括大模型厂商开源仓库和 Hugging Face。对于本地推理,常见模型格式包括 GGUF、MLX 与 Ollama 使用的 Modelfile / 模型封装。

## 2. 模型从哪里来

Hugging Face 是当前最常用的开放模型分发平台之一,可按模型格式、参数规模、量化方式、下载量和任务类型筛选模型。

本地运行时常见选择:

| 类型 | 说明 |
| --- | --- |
| GGUF | 常用于 llama.cpp、LM Studio、Ollama Modelfile 引用 |
| MLX | Apple Silicon 生态常见格式 |
| Ollama Library 模型 | 可直接通过 `ollama pull` 拉取 |
| 自定义 Modelfile | 用本地模型文件构建 Ollama 模型 |

选择模型时需要关注:

- 参数规模
- 量化等级
- 上下文长度
- 显存 / 内存需求
- 是否支持目标运行平台
- 是否需要嵌入模型能力

## 3. 如何运行模型

模型文件记录了神经网络参数。运行模型的本质是用对应运行时加载模型文件,初始化推理引擎,并对外暴露交互入口。

常见方式分为两类:

| 类型 | 代表 | 特点 |
| --- | --- | --- |
| 工具库 | llama.cpp、vLLM | 更适合服务化和工程集成 |
| 桌面 / CLI 软件 | LM Studio、Ollama | 上手快,适合本地验证 |

## 4. LM Studio 方案

LM Studio 适合希望通过 GUI 搜索、下载、加载模型,并快速开启 OpenAI 兼容 API 的场景。

### 4.1 特点

| 项 | 说明 |
| --- | --- |
| 模型格式 | GGUF、MLX |
| 模型来源 | Hugging Face |
| 操作方式 | GUI + CLI |
| API 端口 | 默认 `1234` |
| 优点 | 支持手动模型加载参数,GUI 友好 |
| 缺点 | 同一模型通过 RESTful API 调用时通常排队,并发能力受限 |

### 4.2 基本流程

1. 下载并安装 LM Studio。
2. 在 GUI 中搜索模型。
3. 下载 GGUF / MLX 模型。
4. 加载模型并配置上下文长度、GPU offload 等参数。
5. 开启本地 API Server。
6. 通过 OpenAI 兼容接口调用。

### 4.4 对话接口调用

```http
POST http://127.0.0.1:1234/v1/chat/completions
Content-Type: application/json

{
  "messages": [
    {
      "role": "user",
      "content": "你好"
    }
  ],
  "model": "deepscaler-1.5b-6",
  "stream": true,
  "temperature": 0.7,
  "max_tokens": 2000
}
```

TypeScript 流式调用示例:

```typescript
const url = 'http://127.0.0.1:1234/v1/chat/completions'
const model = 'deepscaler-1.5b-6'

const test = async () => {
  const response = await fetch(url, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      messages: [
        {
          role: 'user',
          content: '你好',
        },
      ],
      model,
      stream: true,
      temperature: 0.7,
      max_tokens: 2000,
    }),
  }).catch((error) => {
    console.error('调用模型 API 失败 =>', error)
    return null
  })

  if (!response || !response.body) {
    console.error('响应为空')
    return
  }

  const reader = response.body.getReader()
  const decoder = new TextDecoder()

  try {
    while (true) {
      const { done, value } = await reader.read()
      if (done) break

      const chunk = decoder.decode(value)
      const lines = chunk.split('\n').filter((line) => line.trim() !== '')

      for (const line of lines) {
        if (line.includes('data: [DONE]')) continue
        if (!line.startsWith('data: ')) continue

        const json = JSON.parse(line.replace('data: ', ''))
        const content = json.choices[0]?.delta?.content || ''
        if (content) {
          process.stdout.write(content)
        }
      }
    }
  } catch (error) {
    console.error('处理流式响应失败 =>', error)
  }
}

test()
```

## 5. Ollama 方案

Ollama 更适合作为本地常驻模型运行服务,提供 CLI、模型仓库、OpenAI 兼容接口与原生 `/api/chat` 接口。

### 5.1 特点

| 项 | 说明 |
| --- | --- |
| 模型格式 | Ollama 模型、Modelfile、GGUF 引用 |
| 模型来源 | Ollama Library、Hugging Face 自定义转换 |
| 操作方式 | CLI |
| API 端口 | 默认 `11434` |
| 优点 | 支持 RESTful API 并发请求,服务化体验好 |
| 缺点 | 使用本地 GGUF 时需要维护 Modelfile 并执行 `ollama create` |

### 5.2 基本流程

1. 下载并安装 Ollama。
2. 通过 `ollama pull` 拉取模型,或准备 GGUF 模型文件。
3. 如使用本地 GGUF,创建 Modelfile。
4. 执行 `ollama create` 构建模型。
5. 通过 CLI 或 API 调用。

### 5.3 使用 Modelfile 引用 GGUF

创建 `Modelfile`:

```text
FROM ./DeepSeek-R1-Distill-Qwen-7B-Q4_K_M.gguf
```

创建 Ollama 模型:

```bash
ollama create deepseek-qwen-7b -f Modelfile
```

运行模型:

```bash
ollama run deepseek-qwen-7b:latest
```

### 5.6 Ollama 原生 API 调用

```typescript
const url = 'http://127.0.0.1:11434/api/chat'
const model = 'deepseek-qwen-7b:latest'

const test = async () => {
  const response = await fetch(url, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      model,
      messages: [
        {
          role: 'user',
          content: '你是谁？中文回答。',
        },
      ],
      stream: true,
      options: {
        temperature: 0,
      },
    }),
  }).catch((error) => {
    console.error('调用模型 API 失败 =>', error)
    return null
  })

  if (!response || !response.body) {
    console.error('响应为空')
    return
  }

  const reader = response.body.getReader()
  const decoder = new TextDecoder()

  try {
    while (true) {
      const { done, value } = await reader.read()
      if (done) break

      const chunk = decoder.decode(value)
      const lines = chunk.split('\n').filter((line) => line.trim() !== '')

      for (const line of lines) {
        if (!line) continue

        const json = JSON.parse(line)
        const content = json.message?.content || ''
        if (content) {
          process.stdout.write(content)
        }
      }
    }
  } catch (error) {
    console.error('处理流式响应失败 =>', error)
  }
}

test()
```

## 6. Ollama 与 LM Studio 对比

| 维度 | Ollama | LM Studio |
| --- | --- | --- |
| 文件格式 | Modelfile、GGUF 引用 | GGUF、MLX |
| 模型来源 | Ollama Library、Hugging Face 自定义转换 | Hugging Face |
| 操作系统 | macOS、Linux、Windows | macOS、Linux、Windows |
| API Server | 支持,默认 `11434` | 支持,默认 `1234` |
| CLI | `ollama` | `lms` |
| GUI | 无 | 有 |
| 模型并发 | 支持并发,受硬件资源限制 | 同一模型通常队列化 |
| 上手体验 | CLI 友好 | GUI 友好 |
| 工程集成 | 更适合服务化 | 更适合本地试验 |

## 7. 并发问题与处理

### 7.1 LM Studio 同一模型排队

问题:通过 RESTful API 调用同一个已加载模型时,请求可能进入队列等待,无法真正并发推理。

处理方式:加载同一个模型文件的多个运行时实例,并使用不同 identifier 区分。

示例:

```bash
lms load model-name --identifier alias-name
```

并发能力取决于硬件资源,尤其是内存、显存、GPU offload 与模型参数规模。

### 7.2 Ollama 自定义模型转换成本

问题:Ollama 使用本地 GGUF 模型时,需要通过 Modelfile 和 `ollama create` 创建模型记录。

处理方式:

1. 将 GGUF 文件放到固定目录。
2. 创建 Modelfile。
3. 执行 `ollama create`。
4. 用模型名进行 API 调用。

这种方式多维护一个 Modelfile,但更利于长期服务化调用。

## 8. 选型建议

| 场景 | 推荐 |
| --- | --- |
| 快速体验、手动调参数、GUI 下载模型 | LM Studio |
| 本地服务化、API 并发、长期集成 | Ollama |
| 需要控制底层推理细节 | llama.cpp / vLLM |
| Apple Silicon 上试验 MLX 模型 | LM Studio 或 MLX 生态工具 |
| 团队统一本地模型服务 | Ollama |
