## 一、问题:为什么"AI 太贵"的第二个口子是大模型滥用

65-66 期讲了 AI 推理的第一层成本——GPU 时长×Token 数量×模型规模×并发量四件事一起算,把"AI 太贵"剥成四种隐藏成本(输入 token / 输出 token / KV cache 显存占用 / 重试风暴)。

67-68 期往**第二层成本**挖——**大模型滥用**。产品把所有请求都打到 GPT-4 这种"专家号"上,80% 的请求其实是常识题、合同日期怎么填、违约金上限多少这种根本不需要专家思考的题。

把一句话模糊的"AI 太贵"剥开,真问题是**模型选型没有分级**——明明社区诊所就能看的病,非要挂三甲医院的专家号,月账单能不爆吗。

真实案例(2024 年某法律 SaaS 平台):

- 80% 的用户问题其实是"合同日期怎么填""违约金上限多少"这类常识题;
- 产品把所有请求都打到 GPT-4;
- 月账单 12 万;
- 改用 LiteLLM 路由器 + 本地 7B 模型做第一道分诊后,月账单降到 4.5 万;
- 效果不降反升——7B 对常识题反而更稳定(没有 GPT-4 那种"过度发挥"的毛病)。

这就是 67 期要讲的核心命题:**多模型路由不是技术问题,是医生分诊**。

## 二、模型路由器对比:5 家厂商一图看清

模型路由器(Model Router)的核心职责是**接收一个请求,根据复杂度/成本/延迟/质量四要素,决定送给哪个模型**。市面上有 5 家主流选择,各有侧重。

### 2.1 五家对比表

| 厂商 | 定位 | 支持模型 | 路由策略 | 自托管能力 | 开源协议 | 价格 |
|---|---|---|---|---|---|---|
| **Not Diamond** | 智能路由+评测 | OpenAI / Anthropic / Google / Mistral 等 20+ | LLM-as-judge + 训练数据预测最优模型 | 不支持,纯 SaaS | 闭源 | 按 token 收 1-2% 加成 |
| **Martian** | 智能路由(LLM 路由) | 同上 | 每个模型训练一个"预测器",预测其他模型在此请求上的表现 | 不支持,纯 SaaS | 闭源 | 企业版报价 |
| **LiteLLM** | 统一 API 网关 | 100+ 模型(含开源/私有) | 简单规则 + 负载均衡 | 支持,Docker / Kubernetes | MIT 开源 | 自托管免费 |
| **OpenRouter** | 模型聚合 + 路由 | 100+ 模型 | 用户指定模型为主,可加 fallback | 不支持,纯 SaaS | 闭源 | 按 token 加 5% 服务费 |
| **Portkey** | AI 网关+可观测性 | 200+ 模型 | 策略引擎(成本/延迟/质量)+ 缓存 | 支持 | Apache-2.0 | 自托管免费,SaaS 版按用量 |

### 2.2 怎么选

- **小团队、想快速跑通**:OpenRouter / LiteLLM。零部署,接 API 就能用。
- **中等规模、要可观测**:Portkey。带 trace/日志/告警,FDE 最爱。
- **大厂、追求最优成本**:Not Diamond / Martian。但要付出数据给路由厂商的代价。
- **私有化部署、金融/政企合规**:LiteLLM / Portkey 自托管。数据不出网。

法律 SaaS 那个案例选的是 LiteLLM——开源、可控、能跑在客户自己的 K8s 上,合规好过关。

## 三、模型能力基准:价格曲线的真相

很多人以为"模型越大越准",这是错觉。来看真实的能力-价格曲线。

### 3.1 MMLU / HumanEval 价格曲线(2024-2025 数据)

把各家模型的 MMLU 准确率(横轴)和每 1M token 单价(纵轴)画一张散点图,会发现一个清晰规律:

- **GPT-4 系列**(gpt-4o / gpt-4-turbo):MMLU 88-92%,单价 $5-10/1M token。在右上角。
- **GPT-4o mini**:MMLU 82%,单价 $0.15/1M token。性价比拐点。
- **Claude 3.5 Sonnet**:MMLU 88%,单价 $3/1M token。性能强但贵。
- **Claude Haiku 4.5**:MMLU 75-78%,单价 $0.25/1M token。同档位最便宜。
- **Qwen3.7-Plus**(阿里云百炼):MMLU 78%,单价 ¥0.4/1M token(约 $0.06)。国产性价比之王。
- **Hunyuan-2.0**(腾讯混元):MMLU 76%,单价 ¥0.5/1M token(约 $0.07)。国产中游。
- **Llama-3.1-8B-Instruct**(本地):MMLU 68%,GPU 自建单价 $0.02-0.05/1M token(摊销后)。

**拐点结论**:MMLU 75-80% 这一档,价格能差 50 倍——Claude Haiku 4.5 是 $0.25,Qwen3.7-Plus 是 $0.06,本地 7B 是 $0.03。

### 3.2 HumanEval(代码能力)曲线

代码场景比通用问答更陡峭:

- **GPT-4 / Claude 3.5 Sonnet**:HumanEval 90%+,单价 $3-10/1M token。
- **GPT-4o mini / Claude Haiku 4.5**:HumanEval 80-85%,单价 $0.15-0.25/1M token。
- **Qwen2.5-Coder-7B / DeepSeek-Coder-V2**:HumanEval 75-85%,本地部署 $0.02/1M token。

代码任务用本地 7B + 提示词工程,80% 的"中等难度"任务(单元测试、CRUD、SQL)都能解,根本用不上 GPT-4。

### 3.3 一句话总结

**不是模型越大越好,是模型能力和你任务的"匹配度"越高越好**。一个合同日期填写的常识题,7B 模型解得比 GPT-4 还稳——因为 GPT-4 太聪明了反而容易过度发挥。

## 五、本地部署:Ollama / vLLM / llama.cpp 三件套

本地部署小模型是降本的关键一环,但三种工具侧重点不同。

### 5.1 Ollama

- **定位**:个人开发者 + 中小团队,**零配置**本地跑模型。
- **优势**:一行命令拉模型、跑推理、自带 REST API。
- **劣势**:生产环境并发能力弱(单机 10 并发就吃力)。
- **适用场景**:开发自测、内部工具、PoC 验证。
- **典型命令**:`ollama pull qwen2.5:7b` → `ollama run qwen2.5:7b` → 自动起 REST API on :11434。

### 5.2 vLLM

- **定位**:**生产级**推理服务,主打高吞吐。
- **优势**:PagedAttention 显存调度 + 连续批处理,GPU 利用率从 20% 提到 70%,**24 倍吞吐**(Hugging Face 2024 公开数据)。
- **劣势**:配置比 Ollama 复杂,需要懂 GPU 调度。
- **适用场景**:中型 SaaS 月调用 100 万 token 以上的生产环境。
- **核心参数**:`--max-num-seqs 256 --gpu-memory-utilization 0.9`。

### 5.3 llama.cpp

- **定位**:CPU + 边缘设备 + **极低显存**部署。
- **优势**:GGUF 量化格式支持 INT4/INT8,7B 模型可塞进 6GB 显存甚至纯 CPU。
- **劣势**:无 web 服务,需要自己包一层 API。
- **适用场景**:Mac mini / 家用 NAS / 边缘盒子跑 7B 模型。
- **典型用法**:模型文件 `Llama-3.1-8B-Instruct-Q4_K_M.gguf`(4-bit 量化,~4.7GB),`llama.cpp` 启动 `llama-server -m model.gguf`。

### 5.4 怎么选

- **开发自测**:Ollama。一行命令搞定。
- **中型生产**:vLLM。吞吐是 Ollama 的 24 倍。
- **边缘 / 家用 / 低成本**:llama.cpp + GGUF 量化模型。
- **混合架构**:vLLM 跑主流量 + Ollama 跑边缘兜底 + llama.cpp 跑 CPU 备用。

## 六、Anthropic Prompt Caching 政策(2024-09 发布)

Prompt Caching 是降本的另一把利器——**同一段上下文(系统提示词 + 长文档)只付一次写费,后续 5 分钟内的请求读费是写费的 10%**。

### 6.1 价格政策(以 Claude 3.5 Sonnet 为例)

- **Cache Write**:首次写入,价格是输入 token 的 **+25%**(即 $3.75/1M token)。
- **Cache Read**:命中缓存后读取,价格是输入 token 的 **-90%**(即 $0.30/1M token)。

### 6.2 怎么用

Anthropic 官方 API 支持 cache_control 字段:

```json
{
  "model": "claude-3-5-sonnet-20241022",
  "system": [
    {
      "type": "text",
      "text": "你是某法律 SaaS 的 AI 助手,只回答中国合同法相关问题..."
    }
  ],
  "messages": [...],
  "tools": [...]
}
```

系统提示词 + 长文档历史会自动缓存。命中后,**写一次的钱能被 5 分钟内的所有请求摊销**。

### 6.3 命中率门槛

官方建议:**命中率低于 30% 不要上**(浪费工程时间,得不偿失)。命中率高的场景:

- **RAG 系统**:同一份知识库被多次查询(每次都带相同的 system prompt + 知识库摘要)。
- **Agent 系统**:同一份 SKILL.md / AGENTS.md 被多次调用。
- **客服系统**:同一份 FAQ + 公司介绍被多个用户重复加载。

### 6.4 OpenAI 自动缓存(2024-10 发布)

OpenAI 也有类似的自动缓存机制:**超过 1024 token 的 prompt 自动缓存**,命中后输入 token 价格 -50%。不需要手动加字段。

## 七、OpenAI Batch API:再砍一刀

OpenAI Batch API 是另一把降本利器:

- **价格**:**50% 折扣**(标准价的 5 折)。
- **限制**:24 小时内返回结果(异步)。
- **适用场景**:对延迟不敏感的任务——批量数据标注、离线 RAG 索引、夜间对账任务。

法律 SaaS 把"夜间离线文档解析"从 GPT-4 切到 Batch API 后,这部分成本直接砍掉一半。

## 八、LiteLLM 路由实战:法律 SaaS 案例拆解

承接第一节那个真实案例——某法律 SaaS 怎么用 LiteLLM 把月账单从 12 万砍到 4.5 万。

### 8.1 改造前

```
用户提问 → 直接打 GPT-4 → 返回
```

- 所有请求都打 GPT-4。
- 月调用 100 万次,平均 800 token/次。
- 月账单:100 万 × 800 × $10/1M = $8,000 ≈ 12 万人民币。

### 8.2 改造后

```
用户提问 → LiteLLM 路由器
            ├─ 简单问题(70%) → 本地 Llama-3.1-8B(Ollama 跑)
            └─ 复杂问题(30%) → Claude Sonnet 4.5(云端)
```

- 复杂度分类器用 GPT-4o mini 当裁判(便宜又快):"这个问题 7B 能解吗?答 yes/no"。
- 70% 走本地 7B:0 月费,只是 GPU 摊销 + 电费。
- 30% 走 Claude Sonnet:30 万 × 800 × $3/1M = $720 ≈ 5000 人民币。
- 复杂度分类器:100 万 × 50 token × $0.25/1M = $12.5 ≈ 90 人民币。
- **月账单从 12 万降到 4.5 万**。

### 8.3 效果不降反升的秘密

听起来"用便宜模型效果应该差吧",但实际跑下来**效果反而变好**:

- GPT-4 太聪明了,对简单问题经常"过度发挥"——答了一堆用户没问的细节,反而让答案变长变糊。
- 7B 对"合同日期怎么填"这种固定答案,反而答得更直接更准。
- 用户满意度反而提升了 5%(脱敏后某 SaaS 的 NPS 数据)。

**反常识金句**:**不是越大越好,是越匹配越好**。

## 九、五条"不是…而是…"金句素材

这些金句直接用于 67-68 期正文,撰稿员可参考但不强制全部使用。

1. **不是模型越大越好,是模型能力和你任务的"匹配度"越高越好。**
2. **不是 AI 太贵,是用贵模型解简单题——大模型滥用是 AI 账单的第二个口子。**
3. **不是路由策略越复杂越好,是分类器越准越好——分诊台不是医院最贵的设备,是医院不崩溃的关键。**
4. **不是本地模型省钱省出来的,是分级诊疗分流出来的——7B 解 70%,大模型解 30%,账单自然降。**
5. **不是提示词缓存越存越省,是命中率高于 30% 才省——命中率低就是给云厂商捐款。**
