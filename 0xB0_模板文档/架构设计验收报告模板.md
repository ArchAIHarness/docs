# 架构设计验收报告模板

> **阅读对象**:架构评审人、技术负责人、AI Review Agent
> **前置阅读**:[架构设计文档模板](../0xB0_模板文档/架构设计文档模板.md) · [架构设计验收清单](../0xB0_模板文档/架构设计验收清单.md)

本模板用于输出标准化的架构设计验收报告。AI Review Agent 或评审人完成检查后,应按此格式记录结构质量、内容一致性、问题清单、评分和验收结论。

## 使用说明

1. AI Review Agent 或评审人对设计文档完成 Review 后,输出此格式的验收报告
2. 逐项打勾检查，列出P0/P1/P2问题
3. 人根据报告结论决定是否通过验收

## 验收报告模板

```
### 基本信息

| 项目 | 内容 |
|------|------|
| 设计文档 | [文档名称] |
| 验收日期 | [YYYY-MM-DD] |
| 验收人 | [姓名/角色] |

### 一、结构质量检查

| 检查项 | 标准 | 结果 |
|--------|------|------|
| 十章完整 | 每章至少有一条非占位符内容 | ✅/❌ |
| 2.6 ADR记录 | 关键决策已记录，且人已确认 | ✅/❌ |
| 章节顺序 | 从抽象到具体 | ✅/❌ |
| 约束明确 | 每章有具体约束（非"待定"） | ✅/❌ |

### 二、内容一致性检查

| 检查项 | 标准 | 结果 |
|--------|------|------|
| 3.x与6.x对应 | 业务限界在服务设计中有对应服务 | ✅/❌ |
| 6.x与7.x对应 | 服务设计在部署架构中有对应配置 | ✅/❌ |
| 约束闭环 | 上层约束能在下层落地 | ✅/❌ |

### 三、问题汇总

| 级别 | 章节 | 问题描述 | 修复建议 |
|------|------|---------|---------|
| P0 | [如2.6] | [如：未记录架构模式选型决策] | [如：补充ADR-001] |
| P1 | [如3.3] | [如：领域边界与微服务划分不匹配] | [如：调整领域边界定义] |
| P2 | [如6.2] | [如：接口契约缺少返回码定义] | [如：补充错误码说明] |

### 四、问题统计

| 级别 | 数量 | 单项扣分 | 小计 |
|------|------|---------|------|
| P0 | N | -10 | -10×N |
| P1 | N | -5 | -5×N |
| P2 | N | -3 | -3×N |
| **合计** | - | - | **-扣分** |

**综合评分**：100 - 扣分 = N/100

### 五、判定规则

| 级别 | 定义 | 修复要求 |
|------|------|---------|
| P0 | 设计存在根本性问题，必须修复 | 暂停上线 |
| P1 | 影响实现质量，建议修复 | 限期整改后上线 |
| P2 | 优化建议，可选修复 | 可上线 |

| 验收结论 | 判定条件 |
|---------|---------|
| 通过 | 无P0/P1/P2问题 |
| 不通过，需修改后重新验收 | 存在P0或P1问题 |
| 不通过，需重新设计 | 存在多个P0问题或设计方向错误 |

### 六、验收结论

- [ ] 通过（无P0/P1/P2）
- [ ] 不通过，需修改后重新验收（有P1）
- [ ] 不通过，需重新设计（有P0）

### 七、核心问题（按优先级）

**必须修复（P0）**：
1. [P0问题]

**建议修复（P1）**：
1. [P1问题]

**可选优化（P2）**：
1. [P2问题]
```
