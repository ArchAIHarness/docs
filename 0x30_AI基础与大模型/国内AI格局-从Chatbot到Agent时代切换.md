# 个人观点：国内AI大模型格局——从Chatbot时代到Agent时代的切换

> 本文档基于 2026 年 6 月公开信息和实际使用体感。判断维度不是跑分，是实际产品体验和竞争格局。

---

## 一、模型能力分层（按实际体感，不看跑分）

跑分可以被优化，用户真用起来好不好才是真话。

**第一梯队：GLM、豆包、DeepSeek**
这三家在实际使用中能力最靠前。DeepSeek 编码推理最强，GLM Agent 原生适配最好，豆包综合能力均衡。

**第二梯队：MiniMax、Kimi、Qwen**
不是不行，各有特色。MiniMax 轻量高效海外走得好，Kimi 长文本和多智能体编排有差异化，Qwen —— 前两年是第一梯队，但 2025 年后掉队了。

看迭代节奏就知道问题：
- Qwen-Plus 这个模型名从 2025 年 12 月起就再也没有更新过，卡了半年
- Qwen3.5（2026-02）发布时，DeepSeek V4 和 GLM-5 已经在前面了
- Qwen3.6（2026-04）发完 20 天，Kimi K2.6 和 DeepSeek V4-Pro 同时出来碾压
- Qwen3.7（2026-05）终于追上，但 DeepSeek 先占了一个月窗口，而且价格便宜 8 倍

每代都被压制，不是它变弱了，是别人迭代更快。

---

## 二、Chatbot 时代的格局（2024-2025）：字节全栈整合能力独一档

只看模型能力字节不是第一。但看 **「模型 + 产品 + 流量 + 场景」的全栈整合能力**，字节确实是独一档。

### 技术布局：双线模型策略

字节在模型层做了两手准备：
1. **自研基本盘**：持续迭代豆包 Pro 系列自研模型，同时布局 LLaMA 优质基座（Triton 推理服务器、自研训练框架），掌握自研核心技术
2. **外部聚合盘**：搭建模型网关，统一接入 GLM、MiniMax、Kimi、DeepSeek 等第三方模型。抗风险能力和供给灵活性远超只做单一模型的同行。不管哪家模型迭代快，字节都能第一时间接进来

这套策略保证了一点：**模型不是我长的，但用户在我这永远能用上当下最好的。**

### 商业闭环：C 端和 B 端都已跑通

- **C 端**：豆包全系产品覆盖日常对话、内容创作、娱乐等大众场景，用户规模成熟，消费端变现模式已经闭环。抖音 7 亿+日活是天然 AI 流量入口
- **B 端 / 开发者侧**：推出 Agents Plan、Coding Plan 等开发者专项计划，通过扣子平台（300 万注册开发者）和火山引擎 MaaS 搭建起可规模化盈利的商业化路径
- **飞书**：企业协作场景，是 Agent 在企业内部落地的天然阵地
- **Seedance**：年化 $20 亿 B 端收入

### 模型网关：上游谁强我用谁

字节的模型网关不仅能接自研模型，还聚合了多家第三方——当 DeepSeek V4 最强时用户能用 DeepSeek，当 GLM-5 最强时用户能用 GLM。**模型是插件，字节的平台才是主体。**

---

**以上是 Chatbot 时代成立的判断**——模型够用 + 产品最强 + 流量最大 + 变现最快 = 赢家。

---

## 三、Agent 时代的格局切换：这才是真正的核心判断

未来是 Agent 的市场。模型是 Agent 的大脑，产品是身体。**脑子偏了，身体能正常吗？**

字节在这个切换期的位置很特殊——它的 Agent 短板不是技术做不了，而是 **手脚被限住了**。

### 为什么手脚被限住：豆包手机事件

2025 年 12 月，字节发布豆包手机，内置系统级 AI Agent。发布一天后：

- 微信、淘宝、美团、支付宝 **联合围剿**
- 安全弹窗封死，外卖只能接京东，微信登录异常
- 一个深入系统底层的 Agent，动了所有人的流量蛋糕

字节从此明白了：**只要你的 Agent 触到别人的核心利益，你就会成为众矢之的。**

所以之后字节的实际策略是猥琐发育：
- 梁汝波 2026 年关键词「勇攀高峰」，但说的是「豆包/Dola 助手应用」，不是系统级 Agent
- 火山引擎 FORCE 大会整场讲「客户信任」「安全体系」「版权合规」「驻场交付」——全是防守话术
- B 端 MaaS 成了主战场，因为不会触发围剿

### 手脚被限后，具体体现在哪

不是能力问题，是战略选择被锁死之后，几个本可以做得更好的方向上显得慢：

- **场景渗透浅**：Agent 产品大多依附豆包、飞书内部场景，不敢往外走——因为一往外走就碰到别人的围墙
- **工具生态薄**：扣子平台的工具插件数量、垂类行业深度适配进度偏慢，不是因为技术做不了，是因为做了就会碰到利益冲突
- **商业模式偏保守**：Agents Plan 本质上还是在打包卖模型和算力，没有真正形成 Agent 原生的技术壁垒——不是因为没能力，是因为一旦做成原生壁垒，它就是那个会被围攻的东西

字节不是没有能力填这些坑，是**现在不敢填**。一旦猥琐发育期过了、联盟松动、或者找到新的切口，字节随时可以全力冲进来。

### 字节不是不能做，是切太早了

手机 Agent 方向是对的，但 2025 年底冲进去的时候：

- 手机厂商的 AI 助手（华为小艺、荣耀 YOYO、vivo 蓝心等）正在筑墙
- 互联网大厂的 App 围墙还没谈拢，直接封杀
- 整个生态根本没准备好

**早了一步，就成了先烈。**

## 四、真正的战场（至少 3-5 年内）在 PC 端的系统级 Agent

这不是说手机不重要。手机肯定是长期战场，但**至少 3-5 年内，手机被捆得太死了**。

为什么？中国厂商什么调性又不是不知道：
- **手机厂商**控制底层权限（华为/小米/OV/荣耀），不会把系统入口让给任何人
- **互联网大厂**各自筑墙（微信/淘宝/美团），不会开放核心数据和流量给别人的 Agent
- 豆包手机事件已经证明：谁先冲进去，谁就被联合围剿

所以 3-5 年内，手机上跑不出真正的系统级 Agent。能跑的都是 **App 级的、割裂的、被手机厂商许可的** Agent——天花板很低。

PC 完全不同：操作系统开放，文件系统、终端、浏览器、IDE 全部可进。这才是能定义新范式的地方。

**手机和 PC 在 Agent 维度上，根本不是同一种竞争：**

| 维度 | 手机端 | PC 端 |
|------|--------|-------|
| Agent 层级 | **App 级**——被手机厂商捆绑，只能在自家 App 或 App 间跳转，割裂而受限 | **系统级**——操作系统开放，可以直接进文件系统、终端、IDE、浏览器 |
| 控制权 | 在手机厂商手里（华为/小米/OV/荣耀都不会给你底层权限） | 在用户手里 |
| 天花板 | 低——本质上还是聊天助手+轻任务 | 高——能替你把活干了：读代码、改配置、跑命令、调 API、持续执行几十分钟 |
| 当前范式 | AI 聊天框争夺战 | 终端 Agent 平台正在被定义 |

### 什么产品在定义 PC 端的新范式

| 产品 | 本质 | 信号 |
|------|------|------|
| **Claude Code** | 终端里的 AI 编程 Agent | 能自主执行几十步任务、调用工具、协调多个 subagent |
| **Codex (OpenAI)** | 开源终端 Agent | 沙箱执行、安全可靠，OpenAI 生态 |
| **OpenCode** | 完全开源、模型无关的 Agent | 不绑定任何厂商，75+ 模型随便换，176K⭐ |
| **WorkBuddy (腾讯)** | 企业 Agent 工作台 | 嵌入微信/企微，连接小程序生态和 IM 场景 |
| **扣子 (字节)** | AI Agent 开发平台 | 300 万开发者的平台，但偏开发层，不是终端 Agent |

这些产品的共同特征：
- 不再是「你问我答」——而是「你说目标，我替你干完」
- 不再是一个对话框——而是能进你的系统、操作你的工具、持续自主执行
- **换个皮肤就是未来新的应用范式**——底层架构已经定了，谁先做出好产品谁赢

字节在这个战场上的位置：**扣子是开发平台层的布局，但没有对标 Claude Code / Codex 的终端 Agent 产品。它在 PC 端系统级 Agent 这个真正的战场上，几乎缺席。**

### 扣子的另一个问题：开发范式还停在上一代

扣子本质是一个**拖拽式 Agent 开发框架**——用可视化工作流编排 Agent。这个定位本身就暴露出问题：

拖拽编排 = 你还是在 **「搭建」一个 Agent**，然后把它发布出去给别人用。这是上一个时代的开发方式。

看看别人在做什么：
- **Manus**：直接给你一个 VM + 聊天界面。Agent 在里面自己装环境、写代码、跑脚本、出结果。你不需要「搭建」它，你跟它说目标就行
- **Kimi**（多智能体编排之后）：也在往 VM + 聊天模式延展——Agent 不是被你搭出来的，而是**在运行环境中自己动起来的**

方向很清楚：**开发范式正在从「搭积木式构建 Agent」变成「Agent 原生运行在 VM/终端里，你通过对话驱动它」**。

扣子在「搭积木构建」这个过渡形态上待了太久，而别人已经进入了「VM + 聊天」的新范式。

而且注意：Claude Code / Codex 本质也是「终端 Agent + 聊天」——只是它们终端里跑的不是 VM，是本机开发环境。底层逻辑一样：Agent 在运行环境中自主行动，不是被你在画布上连出来的。

**扣子的 300 万开发者规模是护城河也是陷阱**——它让你觉得产品能力在增长，但底层范式已经落后了。

## 五、各家在 Agent 时代的处境

### 第二梯队创业公司的逻辑

GLM、MiniMax、DeepSeek 这类模型原生起家的公司，发展起点决定了战略选择——它们靠自研底层大模型立身，自然选择聚焦打磨单点技术能力，而不是铺全栈商业体系。这不是战略失误。

问题在于商业化周期长，单一模型路线抗风险能力弱。长期来看，它们最合适的方向是下沉 AI 基础设施层——夯实模型底座、算力服务、MCP 协议等底层能力。其中 DeepSeek 编码推理最强但缺产品场景，GLM Agent 原生适配最深入且深耕 MCP，MiniMax 走轻量全模态差异化路线、主攻海外。

### 各家公司一览

| 公司 | 脑子（模型） | 身体（产品/场景） | Agent 时代判断 |
|------|------------|----------------|---------------|
| **字节** | ⚠️ 够用但非最好 | ✅ 全栈最强，但手脚被限 | Agent 落地最快，但模型上限受限；Chatbot 时代全栈优势在 Agent 时代权重下降；手机旧战场防守，PC 新战场未有效布局；扣子停留在搭积木构建范式，而 Manus/Kimi 已进入 VM+聊天新范式 |
| **DeepSeek** | ✅ 编码推理最强 | ❌ 无产品/无场景 | 脑子最好但没身体；腾讯已入股，借场景可翻盘 |
| **GLM/智谱** | ✅ Agent 原生适配最深 | ⚠️ 有平台但缺亿级场景 | Agent 基础设施最强，MCP 协议深耕者 |
| **腾讯** | ❌ 混元起步晚、明显弱 | ✅ 微信是核武器（IM+小程序生态） | 模型最弱但场景最强；微信 Agent「小薇」若落地能量最大，但动作太慢 |
| **阿里** | ⚠️ 曾经第一但迭代掉队 | ⚠️ 有场景（云+电商+生活服务）但整合没想清楚 | 最尴尬——占着第一梯队的资源打不出对应的局面，比创业公司更难转身 |
| **MiniMax** | ⚠️ 轻量高效路线 | ⚠️ 海外 B 端为主 | 不做通用 Agent 战场，走差异化全模态路线 |

---

## 六、一句话总结

不是「谁最强」，而是 **竞争维度正在从 Chatbot 时代切换到 Agent 时代**。

- **Chatbot 时代（2024-2025）**：字节全栈整合（双线模型 + C 端闭环 + B 端开发者生态 + 模型网关）独一档。成立。
- **Agent 时代（2026+）**：模型脑子的权重上升，字节的「模型够用+全栈最强」公式被动摇。至少 3-5 年内，真正的战场在 PC 端系统级 Agent（Claude Code / Codex / OpenCode / WorkBuddy 范式），不是手机上的聊天框——不是手机不重要，是手机被厂商围墙和中国互联网的围墙花园捆死了，短期内跑不出真正的系统级 Agent。字节切手机太早被打回来，手脚被限住被迫猥琐发育，扣子停留在上一代开发范式，在 PC Agent 新战场上几乎缺席。但字节的能力没有被否定——一旦生态破口出现，字节仍然是最有能力迅速杀回来的玩家之一。

**格局还在变，没人已经赢了。**
