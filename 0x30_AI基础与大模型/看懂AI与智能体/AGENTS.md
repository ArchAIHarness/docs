本文件是「看懂 AI 与智能体」专栏的协作约束源头，同时承担两个角色：

1. **专栏规划**：主题脉络、读者画像、选题节奏、写作口径、品牌串联。
2. **AI 协作法条**：在该目录下进行任何写作、改稿、配图、目录调整时，AI 助手必须先读本文件，并在其约束范围内执行；与上游工作区 `AGENTS.md` 冲突时，本文件优先于工作区规则。

> 这份文件本身就是专栏第 3 篇要讲的"上下文工程"在内容创作侧的一个具体落地：人立法，AI 执行，体系审计。每写完一篇，回来更新一次。

- **面向读者**：希望系统理解 AI 与智能体基础概念的人，包括两类——
  - 普通人/业务岗：能读懂、能用、能避坑；
  - 工程师/架构师：能接得住底层逻辑，并知道工程化要做什么。

## 三、整体脉络

把专栏按一条主线串起来，避免写成散点。专栏是作者魏祖潇个人知乎专栏《看懂 AI 和智能体》的长线内容体系，面向两类读者同时展开：

1. 普通用户：建立 AI 基础认知，学会在日常场景中正确使用 AI；
2. 工程师、业务架构从业者：理解智能体工程化落地细节，逐步进入生产级实践。

专栏依靠内容分层自然筛选受众：前段降低理解门槛，中段完成实操闭环，后段逐步向专精工程化收敛。全文贯穿「双螺旋自循环」核心观点：**不存在脱离业务场景的通用智能体，智能体必须结合具体业务场景持续演化**。

### 3.2 三大内容价值阶段

长期排期按三大价值阶段推进，不按热点词汇临时拼接：

1. **第一阶段：基础认知板块 + 从零到一实操落地板块**

2. **第二阶段：工程深耕板块**
   - 目标：重点输出系统架构、落地优化、实战踩坑方案；

3. **第三阶段：体系升华板块**
   - 目标：输出作者原创顶层逻辑与成套落地体系；

### 3.3 第六板块的分水岭定位

- 面向零基础普通用户完成理论落地闭环，推荐读者使用 OpenCode 作为日常 AI 交互、任务执行的智能体工具；

- 向后衔接分层记忆、自主推理、知识库检索、多子智能体协作和生产级工程化体系；

### 3.4 知识库检索专题口径

知识库检索专题统一沿用以下实操观点：

- 纯向量检索是过渡型方案，不作为最终方法论中心；
- 纯向量方案常见短板包括流程固化、使用成本高、脱离真实业务逻辑；
- 优先基于人类业务维度搭建结构化检索，再搭配 Skill 的渐进式披露机制；
- 向量检索只作为模糊匹配和补充召回手段；
- 重点不是“让 AI 查资料”，而是“让 AI 在正确业务边界内查到正确资料，并能解释依据”。

### 第 3 篇（下一篇·首选）：上下文是什么？为什么 AI 会"忘"，又为什么会"跑偏"

- **解决的问题**：AI 凭什么判断当前该做什么；为什么"刚说过又忘了"；为什么资料喂越多反而越糊涂。
- **核心论点**：模型决定上限，上下文决定下限。
- **建议骨架**：
  1. AI 不是没记性，它每次只看眼前这张纸——上下文窗口的直觉解释；
  2. 它看到的不是"字"是 Token——Token 是计费单位也是注意力单位；
  3. 为什么"刚说过又忘了"——会话和上下文不是一回事；
  4. 为什么资料越多反而越糊涂——上下文不是越长越好，是越相关越好；
  5. Agent 为什么需要上下文管理——承接第 2 篇，引出工具返回、记忆、RAG 都是上下文工程；
  6. 普通人怎么用这个认知——怎么开会话、怎么贴资料、什么时候开新会话；
  7. 工程师真正要做的事——上下文工程比 Prompt 工程更底层，AGENTS.md 就是这件事的产物；
  8. 结语——模型决定上限，上下文决定下限。
- **候选标题**：
  - 《AI 很强，但为什么还会"忘"？看懂上下文，你就知道怎么和它合作》（已采用）
  - 《AI 为什么会"忘"？看懂上下文，你就知道怎么和它合作》
  - 《AI 不是没记性，它只是每次都从一张白纸开始》
- **配图建议**（沿用 assets/ 规范）：
  - 上下文窗口 = 一张有限的纸；
  - Token 拆分示意；
  - 会话 vs 上下文的差异；
  - 长上下文 vs 相关上下文的对比；
  - 上下文工程在 Agent 闭环中的位置（呼应第 2 篇的闭环图）。

### 第 4 篇：AI 怎么从“会回答”变成“会干活”？看懂 Tool、Skill 和 MCP

- **承接点**：第 3 篇说 AI 每次只能看见上下文，这一篇说明 AI 如何借助外部能力真正执行动作。
- **核心论点**：Tool 决定 AI 能操作什么，Skill 决定 AI 按什么方法做事，MCP 决定 AI 怎么标准化连接更多外部能力。
- **关键概念**：Tool、Skill、MCP、外部能力、能力获取渠道、能力供给、权限边界、审计。
- **普通人价值**：知道这些能力是干什么的、从哪里遇到，以及授权前如何判断边界。
- **从业者价值**：意识到未来很多系统不只是给人用，也要给 Agent 用；业务系统、专业流程和行业经验都可以封装成 AI 可调用、可复用、可审计的能力。
- **品牌钩子**：MCP 与 Agent Workflows 都是 ArchAIHarness 四根支柱的一部分，自然引出 `agent-workflows`。

### 第 5 篇：提示词到底是什么——不是技巧，是预测前提

- **承接点**：上下文决定 AI 看见什么，Tool/Skill/MCP 决定 AI 能做什么；提示词是人把目标、边界、输入、输出和验收标准交给 AI 的任务契约。
- **核心论点**：好的 Prompt 不是"咒语"，是把任务、角色、约束、示例、验收标准结构化交付给模型。
- **关键概念**：角色设定、任务定义、输入输出格式、Few-shot、验收标准、为什么"模板拼凑"会失效。
- **普通人价值**：怎么把模糊需求拆成清晰输入。
- **工程师价值**：Prompt 是接口契约，不是文案。

### 第 6 篇：RAG 是什么——AI 怎么用你的私有资料

- **承接点**：上下文窗口有限，资料要"按需取"。
- **核心论点**：RAG 不是给 AI 装硬盘，是给 AI 一个图书管理员。
- **关键概念**：向量、检索、召回、相关性、为什么 RAG 也会"找错书"、什么场景该用 RAG 什么场景不该用。
- **普通人价值**：知识库为什么不是"把文档丢进去就行"。
- **工程师价值**：召回质量、切片策略、评测集。
- **长期口径**：该专题不把纯向量检索作为最终答案，而是强调结构化业务检索优先、Skill 渐进式披露辅助、向量检索作为模糊匹配补充。

### 第 7 篇：从 Agent 到 Multi-Agent 与工作流

- **承接点**：单个 Agent 闭环讲完了，复杂任务怎么拆成多个 Agent 协作。
- **核心论点**：Multi-Agent 不是堆人头，是分工、边界、交接、审计。
- **关键概念**：编排者/执行者、职责边界、上下文交接、失败回滚、人工接管点。
- **工程师价值**：把"AI 工作流"落到 Agent Workflows 这一支柱。

### 第 8 篇（收口）：AI 协作的工程方法论

- **作用**：把前 7 篇收成一条方法论，沉淀为"看完整个专栏后，你应该掌握的 5 个判断力"。
- **预期内容**：
  - 怎么判断一个任务该不该交给 AI；
  - 怎么判断一个 Agent 是否可靠；
  - 怎么判断 Prompt 写得好不好；
  - 怎么判断知识库/RAG 是不是用对了；
  - 怎么判断你的团队是不是在做"AI 工程化"，而不是在做"AI 玩具"。
