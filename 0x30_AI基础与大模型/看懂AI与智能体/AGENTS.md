# AGENTS.md · 看懂 AI 与智能体

本文件是「看懂 AI 与智能体」专栏的协作约束源头，同时承担两个角色：

1. **专栏规划**：主题脉络、读者画像、选题节奏、写作口径、品牌串联。
2. **AI 协作法条**：在该目录下进行任何写作、改稿、配图、目录调整时，AI 助手必须先读本文件，并在其约束范围内执行；与上游工作区 `AGENTS.md` 冲突时，本文件优先于工作区规则。

> 这份文件本身就是专栏第 3 篇要讲的"上下文工程"在内容创作侧的一个具体落地：人立法，AI 执行，体系审计。每写完一篇，回来更新一次。

## 一、专栏定位

- **面向读者**：希望系统理解 AI 与智能体基础概念的人，包括两类——
  - 普通人/业务岗：能读懂、能用、能避坑；
  - 工程师/架构师：能接得住底层逻辑，并知道工程化要做什么。
- **核心承诺**：不堆公式、不抄论文，用最少的概念讲清楚 AI 和 Agent 的工作方式与边界。
- **品牌主张对齐**：每篇收尾自然落到「人定义目标和边界，AI 在边界内执行，系统负责验证和审计」。

## 四、选题清单与排期

### 第 3 篇（下一篇·首选）：上下文是什么？为什么 AI 会"忘"，又为什么会"跑偏"

- **解决的问题**：AI 凭什么判断当前该做什么；为什么"刚说过又忘了"；为什么资料喂越多反而越糊涂。
- **核心论点**：模型决定上限，上下文决定下限。
- **建议骨架**：
  1. AI 不是没记性，它每次只看眼前这张纸——上下文窗口的直觉解释；
  2. 它看到的不是"字"是 Token——Token 是计费单位也是注意力单位；
  3. 为什么"刚说过又忘了"——会话和上下文不是一回事；
  4. 为什么资料越多反而越糊涂——上下文不是越长越好，是越相关越好；
  5. Agent 为什么需要上下文管理——承接第 2 篇，引出工具返回、记忆、RAG 都是上下文工程；
  6. 普通人怎么用这个认知——怎么开会话、怎么贴资料、什么时候开新会话；
  7. 工程师真正要做的事——上下文工程比 Prompt 工程更底层，AGENTS.md 就是这件事的产物；
  8. 结语——模型决定上限，上下文决定下限。
- **候选标题**：
  - 《AI 很强，但为什么还会"忘"？看懂上下文，你就知道怎么和它合作》（已采用）
  - 《AI 为什么会"忘"？看懂上下文，你就知道怎么和它合作》
  - 《AI 不是没记性，它只是每次都从一张白纸开始》
- **配图建议**（沿用 assets/ 规范）：
  - 上下文窗口 = 一张有限的纸；
  - Token 拆分示意；
  - 会话 vs 上下文的差异；
  - 长上下文 vs 相关上下文的对比；
  - 上下文工程在 Agent 闭环中的位置（呼应第 2 篇的闭环图）。

### 第 4 篇：提示词到底是什么——不是技巧，是预测前提

- **承接点**：上下文是 AI 看到的全部世界，提示词是你主动构造的那部分。
- **核心论点**：好的 Prompt 不是"咒语"，是把任务、角色、约束、示例、验收标准结构化交付给模型。
- **关键概念**：角色设定、任务定义、输入输出格式、Few-shot、验收标准、为什么"模板拼凑"会失效。
- **普通人价值**：怎么把模糊需求拆成清晰输入。
- **工程师价值**：Prompt 是接口契约，不是文案。

### 第 5 篇：工具与 MCP——Agent 的手脚是怎么长出来的

- **承接点**：第 2 篇说 Agent 需要工具，这一篇说工具到底怎么接进来。
- **核心论点**：工具不是越多越好，工具是契约——名字、参数、返回、权限、副作用都要可解释。
- **关键概念**：函数调用、MCP 协议、只读/写入/危险动作分级、工具描述质量、工具返回如何回到上下文。
- **品牌钩子**：MCP 是 ArchAIHarness 四根支柱之一，自然引出。

### 第 6 篇：RAG 是什么——AI 怎么用你的私有资料

- **承接点**：上下文窗口有限，资料要"按需取"。
- **核心论点**：RAG 不是给 AI 装硬盘，是给 AI 一个图书管理员。
- **关键概念**：向量、检索、召回、相关性、为什么 RAG 也会"找错书"、什么场景该用 RAG 什么场景不该用。
- **普通人价值**：知识库为什么不是"把文档丢进去就行"。
- **工程师价值**：召回质量、切片策略、评测集。

### 第 7 篇：从 Agent 到 Multi-Agent 与工作流

- **承接点**：单个 Agent 闭环讲完了，复杂任务怎么拆成多个 Agent 协作。
- **核心论点**：Multi-Agent 不是堆人头，是分工、边界、交接、审计。
- **关键概念**：编排者/执行者、职责边界、上下文交接、失败回滚、人工接管点。
- **工程师价值**：把"AI 工作流"落到 Agent Workflows 这一支柱。

### 第 8 篇（收口）：AI 协作的工程方法论

- **作用**：把前 7 篇收成一条方法论，沉淀为"看完整个专栏后，你应该掌握的 5 个判断力"。
- **预期内容**：
  - 怎么判断一个任务该不该交给 AI；
  - 怎么判断一个 Agent 是否可靠；
  - 怎么判断 Prompt 写得好不好；
  - 怎么判断知识库/RAG 是不是用对了；
  - 怎么判断你的团队是不是在做"AI 工程化"，而不是在做"AI 玩具"。

## 五、写作口径

- **语言**：中文，短句优先，少用术语；术语第一次出现时一定给直觉解释。
- **结构**：每篇 6-8 个小节；每节一个核心点；不要一节塞两个概念。
- **风格**：先给直觉，再给原理，再给"普通人怎么用"，最后给"工程师要关心什么"。
- **配图**：每篇 3-5 张，统一放在 `assets/<文章 slug>/` 下，按编号命名（如 `02-...png`），README 同步更新索引。
- **收尾**：避免"未来已来"式空话，落到一句可执行的判断。

### 6.3 通用底线

- **不夸大**：不写"颠覆""引爆""未来已来"，不虚构任何数据或战绩。
- **不替代**：引导读者去 GitHub，不要把所有结论都塞进文章里。
- **可验证**：所有提到的仓库都必须真实存在、可访问、内容与文章主张一致。
